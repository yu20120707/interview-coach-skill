# Project Deep Dive

A Project Deep Dive is the factual and decision substrate beneath one or more Storybank stories. It does not replace STAR delivery.

## Guided sequence

Ask one focused question at a time:

1. What business/user problem existed?
2. What was the architecture or operating context?
3. What did the candidate personally own?
4. What decisions did they make and why?
5. Which alternatives were considered?
6. What failed or nearly failed?
7. How were results measured and attributed?
8. What changed afterward and what did they learn?

Record unknowns in `open_questions`; never fill them with plausible guesses.

## Links

- `project_id` links Deep Dive ↔ Claims.
- `story_ids` link Deep Dive ↔ Storybank.
- A story may select only the subset needed for a particular competency.
- Multiple stories may refer to the same project without duplicating project facts.

## Conflict handling

If Storybank prose conflicts with the Deep Dive:

1. show the exact conflict;
2. ask which version is accurate;
3. update the authoritative fact record;
4. revise dependent story/Claim text;
5. preserve a short version note.

Do not silently choose the more impressive version.
