3.自注意力机制有了解过吗？讲一下？  
我当时回答的时候首先讲了公式的原理，然后把那个公式给背了一遍。  
自注意力机制的核心是让每个token动态地聚合全局信息。具体流程如下：  
（1）输入序列X经过线性变换得到Q、K、V；  
（2）计算Q和K的点积，除以√dk防止梯度消失；  
（3）经过softmax得到注意力权重；  
（4）权重乘以V得到输出表示。  
公式为：Attention(Q,K,V) = softmax(QK^T / √d_k) V  
为了增强表达能力，还会使用多头注意力（Multi-Head Attention），即并行多个attention头，最后拼接输出。  
4.为什么每一次问大模型相同的问题的答案都是不一样的？  
这个问题我回答的不是很好[吐]，我当时说的是输入之后每一次embedding后的结果所产生的向量都会有所不同，还有一个如果重复问的话在大模型的prompt里面也会意识到这个问题。后面总结了一下，我感觉我可以这样回答：  
因为大模型的生成过程是概率采样的，它不是固定规则输出。  
模型在每一步预测下一个 token 时，会根据 softmax 概率分布随机采样（受 temperature、top-p 等参数影响）。即使输入相同，采样过程中的随机性也会导致输出略有不同。同时，大模型会记忆上下文（prompt），如果你重复问，它也会意识到你在“重复提问”，从而调整语气或风格。  
5.既然你的简历的项目上提到了BGE-Reranker，那你能讲下这些embedding模型跟你简历上面的BGE-Reranker有什么区别吗？  
这个问题其实不算特别难，我当时回答的是embedding模型是用于做输入序列向量化的，而BGE-Reranker是专门用来给引用的文档做一个重排序的。它会将 query 和 document 一起输入，通过交叉注意力判断“相关性分数”，通常比 embedding 模型更精确，但推理速度更慢。

8.为什么现在市面上的模型都采用了decoder-only架构？  
AI这个回答还挺好的[色]：  
因为 decoder-only 架构在 自回归生成 任务上更高效：  
编码器（encoder）负责理解输入，而解码器（decoder）既能理解上下文，又能逐步生成；  
相比 encoder-decoder 架构，decoder-only 模型参数共享、结构简单，训练和推理都更快；  
并且支持“下一词预测”任务，自然适合聊天、代码生成等场景。

13.你能讲一下你对MCP协议的理解吗？  
这个问题回答的不是很好，可以参考AI的回答：  
MCP（Model Context Protocol，模型上下文协议）是由 Anthropic 在 2024 年底提出的一个开放标准协议，它的核心目标是让大语言模型（LLM）能够安全、标准化地访问外部工具和数据源，就像人类使用 USB-C 接口连接各种外设一样  
具体来说，MCP 解决了传统 AI 应用中的几个痛点：  
●工具碎片化：每个 API 都需要单独写适配代码；  
●上下文丢失：模型无法动态获取最新业务数据；  
●安全风险：直接暴露数据库或内部服务存在隐患。  
MCP 通过 客户端-服务器架构实现标准化交互：  
●MCP Host（如 Claude Desktop、自研 Agent）发起请求；  
●MCP Client 负责协议转换和会话管理；  
●MCP Server 封装具体能力（如查询数据库、调用 GitHub API、访问企业知识库）  
举个例子：在我们内部知识库问答系统中，如果用户问“上个月销售额是多少？”，大模型可以通过 MCP 协议安全地调用公司 ERP 系统的查询接口，获取实时数据后再生成回答，而无需将整个数据库暴露给模型。  
目前，OpenAI、百度、阿里、腾讯等都已支持 MCP。比如高德地图就提供了 MCP Server，开发者可以直接调用其导航、POI 查询能力，无需申请 API Key 或写鉴权逻辑  
14.你能讲讲你最近读了什么论文吗？  
我回答我读了DeepSeek-OCR的论文。这篇工作提出了一个非常颠覆性的思路：把长文本“渲染成图像”，再用视觉模型进行高压缩理解。  
传统大模型处理长文档时，Token 数量爆炸（比如 10 页 PDF 可能需要 10,000+ tokens），导致推理慢、成本高。而 DeepSeek-OCR 通过一个叫 DeepEncoder 的视觉编码器，将整页文档图像压缩为 仅 100~256 个视觉 token，再用 3B 参数的 MoE 解码器还原文本。  
最惊艳的是：在 10 倍压缩率下，OCR 精度仍高达 97% 。这意味着，原本需要 8 张 A100 处理的长文档任务，现在单卡就能搞定。  
我认为这项技术对 RAG 系统有重大意义：  
●文档预处理阶段：可以用 DeepSeek-OCR 高效解析 PDF/扫描件，生成结构化文本；  
●长上下文场景：将文档“视觉化”后输入 LLM，大幅降低 Token 消耗；  
●多模态扩展：未来大模型可能不再依赖文本分词器，而是直接“看图理解”世界
