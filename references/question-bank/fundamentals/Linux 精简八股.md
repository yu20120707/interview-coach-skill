## 操作系统

### 1、进程、线程和协程的区别和联系

`进程是资源分配单位，线程是CPU调度单位，协程是用户态调度的轻量级线程，三者在资源占用、切换开销和调度方式上有本质区别。`
- **进程（Process）**
    - 独立虚拟地址空间，每个进程至少有一个线程。       
    - 切换时需要上下文切换（页表、寄存器等），开销大。（切换其他进程时，保存寄存器状态到pcb，将页表从mmu清除）      
    - 稳定性强，一个进程崩溃不会影响其他进程。      
    - 适用于高隔离，高稳定-----浏览器
- **线程（Thread）**  
    - 共享进程资源（内存、文件描述符），但有独立栈和寄存器。     
    - 切换仍需进入内核态，开销比进程小但比协程大。    
    - 多线程通信容易，容易产生竞态条件，因此需要同步（锁、条件变量）。    
    - 适用于高并发处理场景----科学计算
- **协程（Coroutine）**
    - 用户态轻量级执行单元，由应用主动协作调度（非抢占式）
    - 通过**保存和恢复栈**实现上下文切换。    
    - 不能利用多核，需要配合线程实现并行。    
- **联系**
    - 一个进程 → 多个线程 → 每个线程可运行多个协程。      
    - **协程调度完全由用户控制**，线程调度由操作系统控制。
    - 海量I/O并发连接
    
1、进程是资源分配的基本单位，运行一个可执行程序会创建一个或多个进程，进程就是运行起来的可执行程序

2、线程是资源调度的基本单位，也是程序执行的基本单位，是轻量级的进程。每个进程中都有唯一的主线程，且只能有一个，主线程和进程是相互依存的关系，主线程结束进程也会结束。
多提一句：协程是用户态的轻量级线程，线程内部调度的基本单位

> MMU：在CPU中，用于将虚拟地址转为物理地址，有多种用途；虚拟内存、内存保护、分页机制等
> TLB : 类似cache，保存部分页表项，虚拟->物理，先找TLB，找不到去内存，然后加载到TLB

###  1.1、线程与进程的比较
`线程是调度的基本单位，进程是资源分配单位。线程轻量，启动快、切换开销小，但需要处理同步；进程隔离性好，但切换开销大、启动慢.
#### **核心区别（四点）**
1. **调度**
	- **线程**：CPU调度的基本单位，切换开销小。        
    - **进程**：资源分配的基本单位，切换需要更多上下文（页表、文件描述符）。      
2. **并发性**  
    - **线程**：同一进程内可多线程并发执行，共享进程资源。
    - **进程**：不同进程可并发执行，隔离性更强。
3. **资源**
    - **线程**：不独立拥有资源，但共享进程的堆、全局变量、文件，**独立栈**。  
    - **进程**：拥有独立地址空间、文件描述符、堆和数据段。    
4. **系统开销**
    - **线程**：创建销毁仅需维护少量寄存器、线程栈，开销小。    
    - **进程**：需分配/销毁task_struct、地址空间，开销大。
        

### 2. 进程与线程模型了解多少？
`进程安全性强但开销大，线程轻量适合高并发，但要注意同步问题。场景上，Web 服务器偏线程，浏览器偏进程。`
#### 一、核心区别
- **进程**：操作系统**资源分配的基本单位**，拥有独立的地址空间（代码段、数据段、堆、栈），进程间隔离好，但切换成本高，需要切换页表、刷新 TLB。 
- **线程**：**CPU 调度的基本单位**，同一进程内的线程共享堆、全局变量、文件描述符，但每个线程有自己的栈和寄存器，切换轻量，创建销毁开销远小于进程。
  
#### 二、多线程模型
- 共享进程内存，通信方便，但要处理**同步互斥**问题。
- 示例：  
    QQ 中，一个线程处理聊天，一个线程处理文件传输；Web 服务器中，一个线程处理请求，一个线程处理日志。
- 风险：  
    `i = i + 1` 不是原子操作，可能被线程切换打断，导致数据不一致 → 需要**锁**或**原子操作**。
    
#### 三、多进程模型
- 各进程相互隔离，安全性高，互不影响；通信需 IPC（管道、消息队列、共享内存）。
- 示例：  
    浏览器采用**多进程架构**，页面崩溃不会影响其他页面；Nginx 用**多进程**保证稳定性。
- 代价：  
    上下文切换比线程开销大（虚拟地址空间切换、页表刷新）。
    
#### 四、适用场景
- **多线程**：适合**高并发 I/O 密集型**场景（如 Web 服务器、IM）。
- **多进程**：适合**安全性、稳定性要求高**的场景（浏览器、数据库、服务守护进程）。
    


### 3. 内存池（Memory Pool）

`内存池就是提前申请一大块内存，用来管理小块分配，减少频繁 malloc/free 的开销和碎片问题。
**为什么要用？**
- 系统调用分配内存的开销大，频繁分配释放会拖慢性能。
- 能避免内存碎片，内存更可控。
- 在高频场景，比如网络服务器、游戏引擎，非常常用。
**怎么做？**
- 启动时先申请一块大内存。
- 用一个**空闲链表**管理小块，分配就从链表拿，释放就挂回去。
- 为了效率，还会用**分级内存池**（按块大小分组），甚至**线程本地池**，减少锁竞争。
    
### 4) 内存管理
 
`内存管理主要做 分配、扩展、映射、保护，核心目的是提高效率和安全性。
#### 四个关键词
1. **分配**
    - 给进程分内存，用完回收，常用策略有首次适应、伙伴系统。    
2. **扩展**
    - 用虚拟内存，让小内存跑大程序，按需加载+页置换。  
3. **映射**
    - 逻辑地址转物理地址，靠页表 + TLB 加速。     
4. **保护**
    - 防止越界，保证进程隔离，硬件（MMU）+页权限实现。

### 5) 内存写漏`
`内存写漏就是写了但是没真正落地，常见在 I/O 缓冲或者多线程写的时候。原因一般是缓冲没刷新或者线程覆盖。解决的话就是显式 flush、用事务，或者并发场景加锁`
#### 核心要点
1. **定义**
    - 数据写到了缓冲区，但没及时刷新到目标（文件、磁盘、网络），导致最终数据丢失。
2. **常见原因**
    - 缓冲未刷新（I/O 缓冲 write 后未 flush）。
    - 程序崩溃或异常退出，缓冲数据还没写出。   
    - 多线程并发写入，没有加锁，最后的写被覆盖。    
3. **解决办法**
    - 显式 `flush()` 或 `fsync()`，关闭缓冲机制。
    - 用事务或 WAL（日志先行）保证一致性。    
    - 并发场景下加锁或使用原子操作。
---

### 6) 频繁内存分配释放问题
`就是频繁申请和释放内存，会拖慢程序，还容易碎片化。一般用内存池提前申请大块内存或者对象复用来优化。`

#### **核心要点**
1. **问题表现**
    - 程序中频繁调用 `malloc/free` 或 `new/delete`。
    - 会造成 **系统开销大**（每次分配都要操作内核管理结构）。
    - 容易产生 **内存碎片**，长期运行后占用更多空间。
2. **产生原因**
    - 频繁创建临时对象。    
    - 大量小对象反复分配释放。     
    - 缺乏内存复用策略。    
3. **解决办法**
    - 使用 **内存池** 或对象池：提前申请大块内存，然后分配小块给对象。  
    - 尽量重用对象，减少重复分配。    
    - 对小对象使用 **固定大小分配器**，减少碎片。

### 7) 大内存分配处理
`大内存分配的话，单次申请开销大，还容易碎片化。一般做法是预分配大块内存，或者用 mmap 映射，甚至用专门的大对象内存池，这样复用效率高，性能也稳。`
### **核心要点**
1. **问题表现**
	- 分配数 MB 甚至 GB 级别内存时，系统调用成本高。    
    - 内存对齐和页边界问题更明显，容易产生**内存碎片**。    
    - 大对象频繁创建销毁，可能导致性能瓶颈。    
2. **处理策略**
    - **预分配**：程序启动时或业务高峰前一次性申请大块内存。
    - **内存映射（mmap）**：对于非常大的对象，可以直接映射到虚拟内存，避免堆管理开销。
    - **内存池/对象池**：专门为大对象设计池，提高复用率。
    - **延迟释放**：避免频繁 `free`，可做批量释放或缓存管理。
    - **分块管理**：将大块拆成可控小块，根据使用情况动态合并和回收。


### 8) 虚拟内存、堆栈溢出
`虚拟内存让程序能用比物理内存大的空间，但堆和栈都有限。堆太大或者内存泄漏会占满虚拟内存，栈深递归或大局部变量就会溢出，所以平时写程序要注意释放和分配策略。`
### **核心要点*
1. **虚拟内存作用**
    - 物理内存有限，虚拟内存把它逻辑上扩展成更大的地址空间。    
    - 每个进程有独立地址空间，不同进程互不干扰。    
    - 程序不必一次把全部数据调入内存，按需加载即可。    
2. **堆溢出*
    - 堆是动态分配的内存区域，通过 `malloc`、`new` 等申请。  
    - 如果申请过大或内存泄漏导致持续增长，可能用完可用虚拟内存或触发系统 OOM（Out of Memory）。
    - 处理方式：释放不再使用的内存、用内存池、检测泄漏。     
3. **栈溢出**
    - 栈是函数调用时分配局部变量的区域，空间固定。       
    - 递归深度过大或局部变量过大，会导致栈空间耗尽，程序崩溃。       
    - 处理方式：减少递归深度、不要在栈上分配大数组、可改用堆分配。
 

### 9) 分段与分页区别

`简单说，分段是按程序逻辑划内存，长度可变，更接近人理解的逻辑；分页是按固定大小划内存，更好管理但可能有内部碎片。分段可能有外部碎片，分页可能有页表开销`
### **核心要点**
1. **分段（Segmentation）**
    - 内存按程序逻辑划分，比如代码段、数据段、栈段。     
    - 每段长度不固定，根据需要分配。    
    - 地址由 **段号 + 段内偏移** 构成。     
    - 好处：符合程序逻辑，便于共享和保护。      
    - 缺点：可能产生外部碎片。
        
2. **分页（Paging）**
    - 内存按固定大小页划分（如4KB/页）。      
    - 地址由 **页号 + 页内偏移** 构成。    
    - 页可以映射到任意物理内存，不要求连续。    
    - 好处：消除了外部碎片，易管理。   
    - 缺点：页表维护开销大，有内部碎片（页未满）。
        
### 10) Linux下进程间通信方式？
`管道，消息队列，共享内存，信号，信号量，套接字`
- 管道：
    
- 无名管道（内存文件）：管道是一种半双工的通信方式，数据只能单向流动，而且只能在具有亲缘关系的进程之间使用。进程的亲缘关系通常是指父子进程关系。
    
- 有名管道（FIFO文件，借助文件系统）：有名管道也是半双工的通信方式，但是允许在没有亲缘关系的进程之间使用，管道是先进先出的通信方式。
    
- 共享内存：共享内存就是映射一段能被其他进程所访问的内存，这段共享内存由一个进程创建，但多个进程都可以访问。共享内存是最快的IPC方式，它是针对其他进程间通信方式运行效率低而专门设计的。它往往与信号量，配合使用来实现进程间的同步和通信。
    
- 消息队列：消息队列是有消息的链表，存放在内核中并由消息队列标识符标识。消息队列克服了信号传递信息少、管道只能承载无格式字节流以及缓冲区大小受限等缺点。
    
- 套接字：适用于不同机器间进程通信，在本地也可作为两个进程通信的方式。
    
- 信号：用于通知接收进程某个事件已经发生，比如按下ctrl + C就是信号。
    
- 信号量：信号量是一个计数器，可以用来控制多个进程对共享资源的访问。它常作为一种锁机制，实现进程、线程的对临界区的同步及互斥访问。
    
### 11) fork 读时共享写时拷贝
``fork()` 时，父子进程共享内存，只读共享，写的时候才拷贝一份，这样既节省内存，又加快创建子进程速度。这个机制叫写时复制（COW）`
### **核心要点**
1. **fork 基本行为**
    - 调用 `fork()` 时，会创建一个新的子进程。    
    - 子进程拥有父进程内存的“逻辑副本”，最初并不真正拷贝物理内存。
2. **读时共享（Read）**
    - 父子进程读取同一块内存时直接共享，不占用额外空间。     
    - 因为内容相同，系统没有必要复制。    
3. **写时拷贝（Write）**
    - 当父或子进程尝试修改某块内存时，操作系统才真正分配新内存并拷贝原来的数据。    
    - 写操作只会影响修改方的内存，另一方保持不变。    
4. **好处**
    - 节省内存空间，避免 fork 时一次性复制大量内存。    
    - 提高进程创建速度，尤其是大进程。    

### 12) 互斥锁 + 条件变量
`互斥锁保证同一时间只有一个线程操作共享资源，条件变量则让线程可以等某个条件成立再继续执行，比如生产者等缓冲区空，消费者等缓冲区有东西。`
### **核心要点**
1. **互斥锁（Mutex）**
    - 用来保护临界区，避免多个线程同时修改共享资源。    
    - 基本操作：`pthread_mutex_lock()` 上锁，`pthread_mutex_unlock()` 解锁。      
    - 如果一个线程在锁上阻塞，其他线程必须等待。      
2. **条件变量（Condition Variable）**   
    - 用来让线程等待某个条件成立再执行，或者通知其他线程条件已满足。      
    - 基本操作：    
        - `pthread_cond_wait(&cond, &mutex)`：先解锁互斥锁，线程阻塞，等待条件满足；被唤醒后重新加锁。        
        - `pthread_cond_signal(&cond)`：唤醒一个等待的线程。      
        - `pthread_cond_broadcast(&cond)`：唤醒所有等待线程。           
3. **典型应用：生产者-消费者**
    - 互斥锁保证缓冲区的访问互斥。    
    - 条件变量 `not_full`、`not_empty` 分别通知生产者和消费者继续操作。 
    - 避免忙等，提高效率。
        
### 13) 非堆内存增长问题
`非堆内存增长一般是堆外资源，比如 mmap、线程栈、DirectBuffer 或第三方库分配的内存没有释放。排查可以用 pmap 或 smaps看映射情况，解决办法是确保这些资源及时回收，比如 munmap 或限制线程数、缓存大小。`
### **核心要点*
1. **什么是非堆内存？**
    - 堆内存：`malloc/new` 分配的区域。    
    - **非堆内存**：    
        - 栈空间（递归深度过大导致栈溢出）。        
        - 静态/全局变量占用的内存。       
        - **内存映射文件（mmap）**，如大文件 IO。        
        - 共享内存（IPC）、GPU 显存、JVM DirectBuffer（如果是 Java）。         
        - **第三方库自己管理的内存**（比如 OpenSSL、gRPC）。           
2. **为什么会增长？**
    - 程序频繁调用 `mmap` 或系统接口，但缺乏释放（`munmap`）    
    - 线程数激增，栈空间总和暴涨。    
    - 直接内存（off-heap）分配未回收，GC 无法管理这部分。    
    - 使用缓存但未做容量限制（JVM 的 DirectByteBuffer、C++ 的缓存池）。    
3. **如何排查？**
    - Linux：`pmap <pid>`、`cat /proc/<pid>/smaps` 看 **RSS 与映射段**。    
    - `valgrind --tool=massif`、`jemalloc` 分析内存分配来源。    
    - JVM 场景下，用 `jcmd VM.native_memory summary`。    
4. **解决方案**
    - 检查 `mmap`、共享内存是否及时 `munmap`。      
    - 控制线程数，避免栈过度占用。      
    - 对 DirectBuffer、off-heap 缓存设置上限或及时释放。        
    - 使用内存池避免频繁申请释放。
        


### 14) 堆与栈区别

`栈主要存储局部变量和函数调用信息，由系统自动管理，分配释放快但空间小；堆用于动态分配，空间大但需要手动管理，否则可能内存泄漏或碎片化。`
### **堆与栈的区别**
1. **管理方式**
    - **栈**：由编译器自动分配和释放，无需程序员干预。      
    - **堆**：由程序员显式申请（`malloc/new`）和释放（`free/delete`），否则会造成内存泄漏。
2. **存储内容**    
    - **栈**：函数调用信息（返回地址、参数）、局部变量。        
    - **堆**：动态分配的对象或数组，生命周期不固定。      
3. **内存分配效率**  
    - **栈**：采用连续空间，指针移动，速度快。      
    - **堆**：需要复杂的内存管理（分配、回收），效率低。      
4. **大小限制**   
    - **栈**：空间较小（Linux 默认几 MB），过深递归会栈溢出。      
    - **堆**：理论上受虚拟内存限制，空间大但容易碎片化。     
5. **访问方式**
    - **栈**：LIFO（先进后出），顺序访问。      
    - **堆**：灵活访问，可通过指针随机访问。

### 15) fork 返回值实现

``fork()` 其实是通过内核在复制 PCB 后，在返回时给两个进程不同的返回值来区分身份：父进程返回子进程 PID，子进程返回 `0`。实现上主要靠修改系统调用返回寄存器，并结合写时拷贝优化内存复制。`
#### 为什么 `fork()` 可以这样做？*
- **核心思想**：`fork()` 会复制当前进程的**页表**（采用写时拷贝策略），生成一个几乎一模一样的子进程，然后通过返回值让两个进程知道自己是谁。 
- **返回值规则**： 
    - **父进程**：返回子进程的 PID（>0）。       
    - **子进程**：返回 `0`，表示自己是子进程。       
    - **失败**：返回 `-1`，只在父进程中出现。
#### 实现原理（简化版）*
1. **创建子进程**   
    - 内核复制父进程的 PCB（进程控制块），新建一个 PID。      
2. **复制虚拟地址空间（页表级别）**  
    - **写时拷贝**：不立刻复制物理内存，而是共享，只有当一方写入时才真正分配新页。      
3. **返回值不同*  
    - 内核在 `fork()` 的返回路径上，根据执行上下文修改 `eax`（或对应寄存器）：     
        - 父进程的 `eax` 设置为子进程 PID。        
        - 子进程的 `eax` 设置为 `0`            
    - 因为父子进程执行的是同一段代码，但返回值不同，所以后续执行路径可以分叉。
        

### 16) 用户级线程与内核级线程区别

`用户级线程完全在用户空间调度，切换很快，但没法利用多核，而且如果一个线程阻塞，整个进程就挂掉。内核级线程由内核调度，可以真正并行运行在多个 CPU 上，但切换要陷入内核，开销大`
 **核心区别*

|**对比项**|**用户级线程（ULT）**|**内核级线程（KLT）**|
|---|---|---|
|**管理者**|用户态线程库|操作系统内核|
|**调度**|用户态调度，内核只感知进程|内核负责调度线程|
|**上下文切换**|在用户态切换，无需陷入内核，速度快|需要系统调用，开销大|
|**多核利用**|不支持，多个线程绑定同一内核线程|支持，能在多个 CPU 并行运行|
|**阻塞问题**|一个线程阻塞，整个进程挂起|单线程阻塞，不影响其他线程|
|**实现复杂度**|简单，不依赖内核|复杂，需要内核支持|

**简单理解*
- **ULT** 就像你自己安排任务，不麻烦老板（内核），效率高但只能一条队伍跑。
- **KLT** 就是老板来安排，能开多条队伍跑，但每次请示老板成本高。
    
### 17) 线程池与开销
`线程池复用线程，避免频繁创建销毁的高开销，非常适合高频小任务。不过它也有管理开销，线程过多还会导致上下文切换增加。`

**为什么用线程池？**
- 创建/销毁线程是系统级操作，开销大。
- 线程池复用线程，降低系统调用和上下文切换。
    
 **开销在哪？**
- 线程池本身需要队列、锁来管理任务。
    
- 线程数过多会增加调度压力。
    

### 18) 线程切换内容

**总结：** 保存/恢复通用寄存器、PC、SP、标志位、FPU/SIMD、TLS；进程切换还会更换页表（CR3/TLB）。  
**详解：**

- **用户↔内核**：切到内核栈，中断/系统调用门。
    
- **影响**：TLB 命中率、cache 干扰。

### 19) 线程同步实现

`线程同步一般用互斥锁保证互斥，用条件变量做线程等待，用信号量控制资源数量，读写锁适合读多写少的情况。`
**常见实现方式**
1. **互斥锁（Mutex）**
    - 用于保证同一时间只有一个线程访问临界区。    
    - 典型用法：`pthread_mutex_lock` / `pthread_mutex_unlock`。    
2. **条件变量（Condition Variable）**  
    - 配合互斥锁使用，让线程在条件满足前等待，常用于生产者-消费者。    
3. **信号量（Semaphore）**
    - 可用于同步，也能实现资源计数（适合控制访问同类资源的线程数）。    
    - P 操作（减）、V 操作（加）。    
4. **读写锁（RWLock）**
    - 读操作可以并发，写操作独占。    
    - 适合读多写少的场景。
        
### 20) 互斥同步方法

**一句话总结**：  
互斥同步方法就是确保同一时间只有一个线程访问共享资源，避免竞争条件。

常见互斥同步手段

1. **互斥锁（Mutex）**  
    - 最常用方法，进入临界区前加锁，退出时解锁。       
    - 适合线程间共享资源的互斥访问。       
2. **自旋锁（Spinlock）**
    - 线程在等待锁时不会休眠，而是忙等。    
    - 适合临界区非常短的场景，否则浪费 CPU。    
3. **读写锁（RWLock）**
    - 多个线程可以同时读，但写操作必须独占。    
    - 适合读多写少的场景。     
4. **信号量（Semaphore，取值为0或1时）**
    - 可用作互斥量，用 P/V 操作控制临界区访问。
🔥 **面试简洁答法**：  
“互斥主要用互斥锁，临界区短可以用自旋锁，读多写少用读写锁，信号量也能做互斥。”

### 21) 信号量与自旋锁区别
**一句话总结**：  
信号量是“睡眠等待”，自旋锁是“忙等”，最大的区别在于 CPU 是否空转。

### 核心区别
1. **等待方式**
    - **信号量**：如果资源不可用，线程会阻塞，释放 CPU。       
    - **自旋锁**：线程会一直循环检查锁，消耗 CPU。    
2. **使用场景**
    - **信号量**：适合临界区较长的操作（I/O、长任务），避免 CPU 浪费。  
    - **自旋锁**：适合临界区非常短（几十纳秒），避免线程切换开销。
3. **实现层面**
    - **信号量**：通常需要操作系统调度支持。
    - **自旋锁**：完全在用户态忙等，开销小但容易浪费 CPU。
    
🔥 **面试简洁答法**：  
“信号量会睡眠，适合长临界区；自旋锁忙等，适合短临界区。信号量依赖 OS，自旋锁纯 CPU 级操作。”

### 23) Linux 虚拟地址空间结构

**一句话总结**：  
Linux 给每个进程都分配了独立的虚拟地址空间，把用户态和内核态的内存隔离开，方便管理和保护。

**Linux 虚拟地址空间结构（32 位用户态为例）**
1. **用户空间（User Space）**  
    - **代码段（Text Segment）**：存放程序的可执行指令。  
    - **数据段（Data Segment）**      
        - **已初始化数据**：全局变量和静态变量，程序启动时有默认值。           
        - **未初始化数据（BSS）**：全局变量和静态变量未初始化，运行时自动清零。        
    - **堆（Heap）**：动态分配内存的区域，用 `malloc` / `new` 分配，向高地址增长。    
    - **栈（Stack）**：函数调用时分配局部变量和返回地址，向低地址增长。    
    - **内存映射区（mmap）**：动态库、共享内存、文件映射区域。   
2. **内核空间（Kernel Space）**
    - 内核代码、内核数据、内核堆栈。     
    - 用户态无法直接访问内核空间，访问需要系统调用或陷入内核态。
        
 **面试口语化答法**：  
“Linux 给每个进程划分独立的虚拟地址空间，用户空间存放程序的代码、数据、堆栈和 mmap 区域；内核空间存放操作系统内核，用户程序不能直接访问，保证了安全和隔离。”

### 24) top 排查高占用进程

**总结：** `top` 锁定 PID 与线程后，联动 `pidstat/perf/strace/iostat/vmstat` 定位是算力、锁争用、I/O 还是内存抖动。  
**详解：**

- `top -H -p $pid` 看热点线程；
    
- `pidstat -p $pid 1` 看占用/切换；
    
- `perf top -p $pid` 看函数热点；
    
- `strace -p $pid` 看阻塞点；
    
- `iostat -x 1`、`vmstat 1` 分析 I/O/缺页。

### 25) Linux 进程内存分布

**一句话总结**：  
Linux 进程的内存分布可分为文本区、数据区、堆、栈以及内核映射区，每块用途不同，理解它有助于调试程序和优化内存。

#### 1.文本区（Text Segment）
- 存放程序的可执行代码。
- 通常只读，多进程可共享同一程序文本区。 
- 例如函数和指令存放在这里    
#### 2. 数据区（Data Segment）
-存放全局变量和静态变量。
    - **已初始化的数据 (.data)**：全局/静态变量已赋值。     
    - **未初始化的数据 (.bss)**：未赋值的全局/静态变量，启动时置为 0。    
#### 3. 堆区（Heap）
- 动态分配内存（malloc/new）。
- 从低地址向高地址增长。  
- 程序可控制释放，可重复使用。
- 注意：频繁分配释放或大块分配可能导致性能问题。
#### 4. 栈区（Stack）
- 存放函数调用的局部变量、函数参数和返回地址。
- 从高地址向低地址增长。
- 每个线程有独立栈，栈溢出会导致程序崩溃。
#### 5. 内核空间映射 / mmap 区
- 存放共享库、内存映射文件、共享内存等。  
- 通过 `mmap` 可以把文件映射到进程虚拟地址空间。

**面试口语化说明**：  
“Linux 进程的内存就像一个大房子，不同房间放不同东西：代码在文本区，全局变量在数据区，临时动态用的内存在堆里，每个函数调用用的栈是独立的，还有一些映射文件或共享库在 mmap 区。理解这些区域能帮你快速定位内存泄漏、栈溢出或优化性能。”

### 26) for 循环不断 new 是否 heap-overflow

**总结：** 不一定“溢出”，更常见是“泄漏/耗尽”导致 OOM；溢出是越界写，泄漏是未释放。  
**详解：**

- **未 delete** → RSS 增长直到 OOM；**越界写** 才是 heap-overflow。
    
- **定位**：ASan/Valgrind/massif；修复：及时释放/对象池。

### 27) 死锁与调度算法

**一句话总结**：  
在 `for` 循环中不断 `new` 而不释放，会耗尽堆空间，导致程序异常或崩溃，但严格来说不是“堆溢出”。

#### 1. 发生原因
```cpp
for(int i = 0; i < 1000000; ++i){
    int* p = new int[1024*1024]; // 每次分配 1MB
    // 没有 delete
}
```
- 每次 `new` 都向 **堆（Heap）** 请求内存。  
- 如果不断分配而没有释放，堆空间最终会被耗尽。
    
#### 2. 表现
- 程序可能抛出 `std::bad_alloc` 异常（C++）。  
- Linux 下可能显示 `Killed`，Windows 下可能提示内存不足
- 不会直接覆盖其他内存区域，不像栈溢出会破坏栈空间。
    
#### 3. 与堆溢出的区别

| 类型  | 特点                   | 示例                      |
| --- | -------------------- | ----------------------- |
| 堆耗尽 | 堆空间用尽，程序崩溃或异常        | 大量 `new` 未释放            |
| 堆溢出 | 越界写堆分配内存，可能破坏邻近堆或控制块 | `p[1024*1024] = 0;` 越界写 |
|     |                      |                         |
|     |                      |                         |

#### 4. 防范措施
- 每次 `new` 后及时 `delete`。 
- 使用智能指针（`unique_ptr`、`shared_ptr`）管理动态内存。   
- 对大对象分配使用内存池或批量管理。 

### 28) 进程管理

**一句话总结**：  
进程管理就是操作系统对进程的创建、调度、同步和销毁进行统一管理，保证多个进程高效、安全地共享系统资源。
#### 1. 进程概念
- **定义**：进程是操作系统分配资源的基本单位，也是程序运行的实体。
- **组成**：包括 **代码段、数据段、堆、栈**，以及 **进程控制块（PCB）**，PCB中记录状态、寄存器、PID等信息。
    
#### 2. 进程创建
- **父子关系**：通过 `fork()` 创建子进程，父子共享初始内存。
- **写时拷贝（COW）**：父子进程共享页面，只有写操作时才复制，提高效率。
- **exec 系列**：子进程可调用 `exec()` 加载新程序，实现代码替换。
    
#### 3. 进程状态与调度
- **状态**：就绪（Ready）、运行（Running）、阻塞/等待（Blocked/Waiting）、终止（Terminated）。  
- **调度**：时间片轮转、优先级调度、多级队列等。
- **上下文切换**：保存当前进程寄存器和栈信息，加载下一个进程PCB，实现CPU切换。
    
#### 4. 进程同步与通信
- **互斥**：使用互斥锁（Mutex）或信号量（Semaphore）保护共享资源。
- **同步**：条件变量、管程等保证进程执行顺序，如生产者-消费者问题。 
- **进程间通信（IPC）**：管道、消息队列、共享内存、Socket 等方法。
#### 5. 进程终止
- **正常退出**：`exit()` 或 `return`（在 main 中）。 
- **异常终止**：`abort()` 或接收到终止信号。 
- **资源回收**：父进程可调用 `wait()` 或 `waitpid()` 回收子进程，防止僵尸进程。
    
> 面试小技巧：  
> 讲解时可以画一个 **进程状态转换图**，顺便结合 `fork()` 与 `exec()` 的例子，让回答既直观又易记。
